## Unresolved findings

1. **P1. Sync checks ownership against mutable options, then drops pre-bound models.** `core/SequelizeGuardBase.ts:9` exposes an options object whose schema properties are writable. `SequelizeGuard.ts:154–156` binds actual models once, while `223–241` verifies a receipt and table shapes using the live options. The forced drop at `242–247` uses the pre-bound models. If the public schema options change after construction, receipt validation and destructive DDL can address different namespaces. Capture or make schema-defining options immutable, or derive every checked target from the exact table identities used by DDL. Retain intentional runtime changes to non-schema policy such as `safeGuardDeletes`. Add a test that changes a schema option and asserts rejection before any model drop call.
2. **P1. A failed model sync can leave a receipt claiming tables Guard never created.** `SequelizeGuard.ts:223–229,246–248` writes a complete ownership receipt before synchronizing policy models. `migrations/guard-ownership.ts:146–155,172–202` trusts that receipt on later calls and commits it independently for PostgreSQL and SQLite. If sync stops partway, the receipt covers missing names indefinitely. A same-shape unrelated table later created under an unfulfilled name passes the receipt and schema check on a subsequent forced sync or down. A regular retry can also silently adopt it. Record ownership only for tables whose exclusive creation succeeded, or use an atomic SQLite/PostgreSQL creation path and explicit incomplete state for nontransactional DDL. A recoverable retry must distinguish genuinely created tables from reserved names before any drop or adoption.
3. **P2. Permission-link mutations inconsistently enforce the writer-side ownership binding.** `guard/Roles.ts:281–290` checks the binding in the string-role path but skips it for the model overload. `326–329` removes permissions without checking it. A `sync:false` guard with a mismatched principal model can therefore mutate an initialized namespace even though its authorization and membership mutation paths reject the mismatch. Check binding consistently for policy-link writes on the writer within the same transaction. The hierarchy write lock can remain limited to operations that require graph serialization. Add regression assertions for both overloads and revocation.
