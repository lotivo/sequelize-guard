## I5 recovery and I7 open acceptance

- Save the release run's tarball and digest. If npm accepted a version and later steps fail, inspect npm's exact version/dist-tag/SHA-512 integrity and provenance against the original artifact/source commit. If only the GitHub draft failed, re-run just that failed job or manually create/correct the draft with the already existing tag and correct prerelease status. If npm returned an ambiguous failure but the version exists, recover downstream metadata manually after verifying it. Existing versions are immutable, and the duplicate preflight intentionally stops a new full run for an already published version. After the stable draft is published, recover failed docs generation via the exact stable tag in the docs workflow's manual dispatch on master. If the generated patch conflicts with current master, reconcile the API docs source before retrying the docs change. Keep prerelease docs in the tagged source and stable docs matched to npm latest.
- Once the complete release commit exists, run the entire Node/dialect/package matrix against that commit and archive its artifact digest. A local rehearsal and published historical evidence are insufficient for that gate.
