Start with the SQLite example below. It creates a disposable in-memory database, grants access, checks it, then revokes it. The complete files shown here are also run against the packaged library in CI.

## Install the dependencies

```bash
npm install sequelize-guard "sequelize@^6.37.8" sqlite3
```

## Run the basic example

Save this as `basic.mjs`, then run `node basic.mjs`. Each assertion checks the result shown in the code. A successful run exits without output; a failed assertion reports the mismatch.

```javascript filename="examples/basic.mjs"
import assert from 'node:assert/strict';
import { Sequelize } from 'sequelize';
import { SequelizeGuard } from 'sequelize-guard';

// Automatic initialization is convenient for a new disposable database.
const sequelize = new Sequelize('sqlite::memory:', { logging: false });
try {
  const guard = new SequelizeGuard(sequelize);
  await guard.ready;
  const user = await guard.makeUser();
  assert.equal(await user.can('read article'), false);
  await guard.allow('reader', ['read', 'edit'], 'article');
  await guard.assignRole(user, 'reader');
  assert.equal(await user.can('read article'), true);
  await guard.rmPermsFromRole('reader', 'edit', 'article');
  assert.equal(await user.can('edit article'), false);
  assert.equal(await user.can('read article'), true);
  await guard.rmAssignedRoles(user, ['reader']);
  assert.equal(await user.can('read article'), false);
  assert.equal(await user.can('read article extra'), false);
} finally {
  await sequelize.close();
}
```

`allow()` grants permissions to a role; `assignRole()` gives that role to the user. Removing one action preserves the others. Removing the role assignment then removes the remaining access.

## Use CommonJS

Save this as `basic.cjs` and run `node basic.cjs`. It disables automatic synchronization and waits for the explicit `sync()` call instead.

```javascript filename="examples/basic.cjs"
const assert = require('node:assert/strict');
const { Sequelize } = require('sequelize');
const { SequelizeGuard } = require('sequelize-guard');

(async () => {
  const sequelize = new Sequelize('sqlite::memory:', { logging: false });
  try {
    const guard = new SequelizeGuard(sequelize, { sync: false });
    await guard.ready; // No database work with sync:false.
    await guard.sync(); // Explicit provisioning for this disposable database.
    const user = await guard.makeUser();
    await guard.init().allow('reader').to('read').on('article').commit();
    await guard.assignRole(user, 'reader');
    assert.equal(await user.can('read article'), true);
    await guard.rmAssignedRoles(user, ['reader']);
    assert.equal(await user.can('read article'), false);
  } finally {
    await sequelize.close();
  }
})().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

## Use a custom user with TypeScript

This version uses a string primary key and a required email field. It creates users through the model returned by Guard so TypeScript keeps those application fields.

Save it as `custom-user.ts` and compile it with your application's TypeScript setup before running the emitted JavaScript. `Account.sync()` is only for this disposable demonstration; existing applications run their own account migration first.

```typescript filename="examples/custom-user.ts"
import assert from 'node:assert/strict';
import { DataTypes, Model, Sequelize } from 'sequelize';
import { SequelizeGuard } from 'sequelize-guard';

class Account extends Model<{ uid: string; email: string }> {
  declare uid: string;
  declare email: string;
}
const sequelize = new Sequelize('sqlite::memory:', { logging: false });
try {
  Account.init(
    {
      uid: { type: DataTypes.STRING, primaryKey: true },
      email: { type: DataTypes.STRING, allowNull: false },
    },
    { sequelize, tableName: 'accounts', timestamps: false },
  );
  // Existing applications run their own account migration first.
  await Account.sync();
  const guard = new SequelizeGuard(sequelize, {
    UserModel: Account,
    userPk: 'uid',
    sync: false,
  });
  await guard.ready;
  await SequelizeGuard.migration.up(sequelize.getQueryInterface(), sequelize, {
    UserModel: Account,
    userPk: 'uid',
    sync: false,
  });
  // makeUser() cannot supply required application attributes.
  const user = await guard
    .models()
    .GuardUser.create({ uid: 'acct-1', email: 'test@example.invalid' });
  await guard.allow('reader', 'read', 'article');
  await guard.assignRole(user, 'reader');
  assert.equal(await user.can('read article'), true);
  await guard.rmAssignedRoles(user, ['reader']);
  assert.equal(await user.can('read article'), false);
  await SequelizeGuard.migration.down(
    sequelize.getQueryInterface(),
    sequelize,
    {
      UserModel: Account,
      userPk: 'uid',
      sync: false,
    },
  );
  assert.equal(await Account.count(), 1);
} finally {
  await sequelize.close();
}
```

The final assertion verifies that rolling back Guard's tables leaves the application account intact. See [Users and registered holders](/docs/guide/users) for assignment and registration options.

## Prepare tables with migrations

Save this as `migrations.mjs` and run `node migrations.mjs`. Table creation happens before Guard starts; the application then uses `sync: false`.

```javascript filename="examples/migrations.mjs"
import assert from 'node:assert/strict';
import { Sequelize } from 'sequelize';
import { SequelizeGuard, migration } from 'sequelize-guard';

const sequelize = new Sequelize('sqlite::memory:', { logging: false });
const options = { prefix: 'app_guard_', sync: false };
try {
  // Deployment migration: run once before starting application workers.
  await migration.up(sequelize.getQueryInterface(), sequelize, options);
  // Application startup: no sync/alter/force on an existing database.
  const guard = new SequelizeGuard(sequelize, options);
  await guard.ready;
  await guard.allow('reader', 'read', 'article');
  const user = await guard.makeUser();
  await guard.assignRole(user, 'reader');
  assert.equal(await user.can('read article'), true);
  await migration.down(sequelize.getQueryInterface(), sequelize, options);
} finally {
  await sequelize.close();
}
```

The final `down()` is a demonstration rollback on an in-memory database. Do not put it in normal application shutdown. For deployment ordering and ownership rules, see [Production migrations](/docs/guide/db-migrations).
