The npm package ships one portable integration skill at `skills/sequelize-guard/SKILL.md` and the same [executable recipes](/docs/examples) used by our packed-consumer checks. Contributor instructions in the repository's `AGENTS.md` apply to this monorepo, not to consuming applications.

## Load the installed skill explicitly

From an application with `sequelize-guard` installed, locate `node_modules/sequelize-guard/skills/sequelize-guard/SKILL.md` using your package manager's resolved installation location. Open that file in your agent's context, or copy the **entire** `skills/sequelize-guard` directory to a skill directory supported by your chosen tool. For example, when the package is installed at the usual npm location:

```sh
mkdir -p .agents/skills
cp -R node_modules/sequelize-guard/skills/sequelize-guard .agents/skills/sequelize-guard
```

Only use that destination if your agent supports `.agents/skills`; otherwise follow its documented installation mechanism. Tools do not universally discover skills in `node_modules`. Review copied guidance when upgrading the package.

The skill remains usable when copied: run its `references/installed-package.mjs` detector **from the application directory** to locate the actual resolved version, declarations and examples. It resolves the public package entry point and reads its enclosing manifest on disk, without requiring a `package.json` export. For the usual installation path:

```sh
node node_modules/sequelize-guard/skills/sequelize-guard/references/installed-package.mjs
```

## What to verify

The skill starts with existing models, migrations, verified identity and application tests. It teaches the actual exports, readiness, grant/assignment/check/revocation, custom user keys, and denial versus database failures. Applications authenticate users and protect policy administration themselves; a user ID in a request header is not authentication. Existing databases use explicit deployment migrations with `sync:false`, not force-sync.

Installed `examples/` covers ESM, CommonJS, custom users, migration ownership, verified-session HTTP administration, inheritance/holders/transactions and the offline 6.0.2 upgrade. These run against disposable databases; inspect each fixture before adapting its setup or rollback to your application. Follow [schema setup](/docs/guide/db-migrations), [upgrade guidance](/docs/migration) and [authorization boundaries](/docs/guide/authorization).
