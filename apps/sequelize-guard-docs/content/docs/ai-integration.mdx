If you use an AI coding assistant, give it the guidance shipped with the package installed in your application. That keeps its examples and API assumptions aligned with your dependency.

You can also read and copy the [website examples](/docs/examples/basic) directly. AI tooling is optional.

## What's included

| File or route | Purpose |
| --- | --- |
| `skills/sequelize-guard/SKILL.md` in the npm package | Integration guidance for an assistant working in your application. |
| `examples/` in the npm package | Complete examples tested against that package. |
| Repository `AGENTS.md` | Instructions for contributors working on this monorepo. |
| [/llms.txt](/llms.txt) | A short index of the website documentation. |
| [/llms-full.txt](/llms-full.txt) | Processed documentation, including the public API reference. |

## Load the installed skill explicitly

From your application directory:

1. Locate `sequelize-guard` using your package manager's resolved installation path.
2. Open `skills/sequelize-guard/SKILL.md` from that installation in your assistant's context.
3. If your tool supports installed skills, copy the **whole skill directory**, including its references, to the location it expects.

For a standard npm installation and a tool that supports `.agents/skills`:

```bash
mkdir -p .agents/skills
cp -R node_modules/sequelize-guard/skills/sequelize-guard .agents/skills/sequelize-guard
```

Other tools may use a different destination. Skills in `node_modules` are not universally discovered automatically. Review copied guidance when upgrading the dependency.

### Check which package the assistant is using

Run the supplied detector from the application directory:

```bash
node node_modules/sequelize-guard/skills/sequelize-guard/references/installed-package.mjs
```

It reports the resolved version and the paths to the package, examples and skill. The detector also works from a copied skill directory; keep your working directory at the application so it resolves that application's dependency.

## Review the generated integration

The skill starts from your existing models, migrations, authentication and tests. Before accepting changes, check that the integration:

- Loads the acting user from verified identity, not an untrusted request ID.
- Prepares an existing database with deployment migrations and starts with `sync: false`.
- Awaits startup and handles authorization failures without allowing the operation.
- Protects role and permission administration separately.
- Tests denied access, revocation and database errors in your application.

The shipped examples cover ESM, CommonJS, custom users, migrations, HTTP authorization, inheritance, holders and transactions. They use disposable databases; review setup and rollback code before adapting it.

The installed package is the reference for an older application, even if the website documents a newer release. Automated checks keep packaged guidance and examples connected, but your application tests establish whether the integration works for your users.
