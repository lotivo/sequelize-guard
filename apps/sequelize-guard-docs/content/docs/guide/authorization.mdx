Use permission checks immediately before the operation they protect. Your application establishes who the caller is; Sequelize Guard checks what that caller may do.

## Check a permission

Once your authentication flow has loaded a persisted user:

```typescript
const allowed = await user.can('read article');

if (allowed) {
  // Perform the protected read, with your application's tenant/object checks.
} else {
  // Refuse the operation.
}
```

`can()` includes permissions inherited from parent roles. `cant()` returns the opposite result. Both query the writer database and reject on database errors; an error must not become permission to proceed.

Use role checks when you specifically need direct membership:

```typescript
await user.isA('editor');
await user.isAnyOf(['editor', 'moderator']);
await user.isAllOf(['editor', 'reviewer']);
```

An inherited permission doesn't make the user a direct member of its parent role. See [Roles and inheritance](/docs/guide/roles) for an example.

## Authenticate before authorizing

For each request:

1. Verify the session or credential using your application's authentication system.
2. Look up the persisted user or registered holder for that verified identity.
3. Check the required permission.
4. Apply any tenant or object ownership checks, then perform the operation.

A caller-supplied `x-user-id`, body field, query parameter or unsigned JWT claim is not verified identity. Keep the **acting user** separate from any **target user** named in a request.

The [Express example](/docs/examples/express) shows this flow in code, including the error paths.

### Return the right response

| Situation | HTTP response | Protected operation |
| --- | --- | --- |
| Missing or invalid identity | `401 Unauthorized` | Do not run. |
| Valid identity without permission | `403 Forbidden` | Do not run. |
| Identity service or database failure | A sanitized `5xx` response | Do not run; log details privately. |
| Identity and access checks pass | Your endpoint's success response | Run within the allowed scope. |

A denied check returns `false`. An unavailable database rejects the promise. Keep those cases distinct so clients don't mistake a service outage for a permanent lack of access.

## Protect policy administration

Granting a role or changing its permissions affects other users. Protect those operations with a dedicated administrative permission, such as `manage policy`.

- Validate role names, actions, resources and target IDs supplied by callers.
- Enforce the administrator's tenant and object scope.
- Use CSRF protection for cookie-authenticated writes.
- Grant wildcards deliberately; permissions have no deny-rule precedence.

Guard's built-in methods do not authenticate the administrator for you. The [permission guide](/docs/guide/permissions) covers grants, revocation and transactions.

## Understand when access changes take effect

After revocation commits, a new check outside an older transaction snapshot reads the change from the writer database. Soft-deleted users and registered holders lose access. Manual caches do not supply authorization results.

Two boundaries still matter:

- A check already in progress can see the earlier state.
- A successful check and the later business operation are not automatically one atomic action.

Coordinate database transactions and locking in your application when the business operation needs that stronger guarantee. See [Caching and revocation](/docs/guide/caching) for details.

Store durable audit history and privilege expiry in application-managed storage. Guard events are best-effort notifications within one process; timers alone cannot enforce expiry across restarts and workers.

## Report a security problem

[Report vulnerabilities privately](https://github.com/lotivo/sequelize-guard/security/advisories/new). Include package, Node, Sequelize and database versions plus a minimal reproduction. Leave out secrets and customer data. The [security policy](https://github.com/lotivo/sequelize-guard/blob/master/SECURITY.md) explains release support and dependency exposure limits.
